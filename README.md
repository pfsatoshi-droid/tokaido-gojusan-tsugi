# ぷっぷーとぷーぷの東海道五十三次

二匹と一緒に日本橋から京都・三条大橋まで旅する、レスポンシブな Web アプリです。

## 開発

Node.js 20.19+ または 22.12+ が必要です（クラウド環境では Node.js 24 で確認）。

```sh
npm ci
npm run dev
```

## 検証

```sh
npm run build
npm test
```

ブラウザテストは、このクラウド環境の `/usr/bin/chromium` を利用します。別の環境では `playwright.config.js` の executablePath を変更してください。

## 機能

- 日本橋・53宿・三条大橋の55地点を表示
- 地域と宿場名による絞り込み
- OpenStreetMap の道路地図、55地点の宿場ピン、拡大・縮小、訪問済み表示
- 現在地表示（利用時のみ位置情報の許可を要求、アプリには保存しません）
- 日本橋から三条大橋まで全54区間の徒歩ルートを地図内に常時表示（選択中の区間を強調）
- 補助として Google マップの徒歩経路リンク
- 宿場の紹介、前後の宿場への移動
- 訪問記録、進捗表示、旅のメモ
- localStorage によるブラウザ単位の保存（サーバー同期はありません）

イラストは旅の雰囲気を表すオリジナル SVG で、各宿場の実景ではありません。人物のデザインは本アプリ用の仮デザインです。フォントは Google Fonts を利用し、取得できない環境では端末のフォントに切り替わります。

## マップ

上部の「マップ」または宿場一覧の表示切り替えから開けます。宿場を選ぶと道路が見える縮尺まで拡大します。「宿場の紹介」で紹介画面を、「Google マップで徒歩経路」で外部の経路検索を開きます。地図は Leaflet と OpenStreetMap の標準タイルを使用し、表示中の範囲のみ取得します。地図の一括ダウンロードやオフラインキャッシュは行いません。

宿場ピンは宿場付近の概略位置です。徒歩経路を開いた先で出発地と目的地を確認してください。旧東海道の厳密な道筋は収録していません。

道路地図には `tile.openstreetmap.org`、徒歩経路には `www.google.com` への通信が必要です。現在地は HTTPS 上で許可された場合に表示します。地図や位置情報を利用できない場合は画面に案内を表示します。クラウド環境での操作テスト7件は成功しました。経路描画テストは固定のサービス応答を使用しており、ネットワーク制限で実タイル・実経路取得と公開サイトの表示は未確認です。

徒歩ルートは `routing.openstreetmap.de` の FOSSGIS routed-foot バックエンドで取得します。OSRM API の URL は `/routed-foot/route/v1/driving/` ですが、利用するバックエンドは徒歩用です。全55地点を1回のリクエストで経由し、全54区間をまとめて取得します。青い全ルートは宿場選択・検索・地域絞り込みで消えず、選択区間だけ橙色で強調します。取得結果はページ内メモリで再利用し、宿場変更のたびに再検索しません。現在地はルートサービスに送信せず、宿場座標だけを送信します。失敗時には架空の直線を表示せず再読み込みを案内します。全区間の旧東海道の検証済みルートではありません。

## GitHub Pages で開く

公開用ファイルは `docs/` に含まれています。GitHub の Settings → Pages で Source を「Deploy from a branch」、Branch を `main`、Folder を `/docs` にして Save を押すと公開できます。

公開先: https://pfsatoshi-droid.github.io/tokaido-gojusan-tsugi/

アプリを更新した場合は `npm run build:pages` で公開用ファイルを再生成し、`docs/` もコミットしてください。公開設定の有効化とデプロイ完了が必要です。

## 宿泊地ごとの旅程プランナー

「マップ」内の「何泊で、どこまで歩こう？」で、地図を押す・宿場を選ぶ・ホテル名や住所を検索する、のいずれかで宿泊地を登録します。1日目は日本橋から1泊目、2日目は1泊目から2泊目という順で徒歩距離と所要時間を表示します。最大20泊まで保存でき、名前変更・順序変更・削除・ピンのドラッグに対応します。

計画はブラウザのlocalStorageに保存します。距離と時間はFOSSGISの徒歩経路の目安で、休憩や観光は含まず、旧東海道や既存の青線に沿う保証はありません。経路に宿泊地の座標を送信します。場所検索はユーザーの検索操作時だけNominatimへ送信し、自動補完は行いません。検索できない場合も地図から登録できます。検索・経路サービスへの実接続は環境の通信制限により未確認です。固定応答を用いた保存・日別計算・並べ替え・エラー表示を含むブラウザテスト10件が成功しています。

### 25kmプランと縦の旅程図

初回は全線の徒歩ルートを取得した後、道路に沿った累計約25kmごとの目安ピンと、京都の到着点を自動作成します。保存済み計画は自動で置き換えず、「1日約25kmのプランを作る」から置き換えを選べます。ピンは宿泊施設の確認済み位置ではありません。最終日は25km未満になることがあり、各日の再検索により実際の距離も変わり得ます。

縦の旅程図は日本橋→各宿泊地点→京都の順に表示し、各日の徒歩距離・時間・累計距離を示します。表示間隔は縮尺ではありません。全線取得に失敗した場合は自動プランを作らず、手動で地点を追加できます。最大60地点に対応します。ブラウザテスト11件が成功しています（経路サービスは固定応答で検証）。

### 宿泊地点の周辺ホテル検索

宿泊ピン、縦の旅程図の地点、または日別カードの「近くのホテルを探す」を押すと、周辺ホテル検索の案内が開きます。リンクは地点の緯度経度を指定した Google マップのホテル・旅館検索です。外部サイトで開き、料金・空室・予約は検索先で確認します。

周辺ホテル検索はOverpass APIから半径3kmの宿泊施設を取得し、直線距離順に表示します。「この宿を宿泊地にする」でピンを施設へ移し日別距離を再計算します。未登録施設・空室・営業状況は取得できません。失敗時は地点を中心にしたGoogle マップ検索を利用できます。検証は固定応答による検索条件・範囲外除外・宿泊地点変更のブラウザテストで行っています。

### 施設名検索の検証例

2026-11-10、「東横INN横浜新子安駅前」の完全名称検索はNominatimでは0件でした。公式 https://www.toyoko-inn.com/search/detail/00159/ の施設名・住所（子安通2-240-32）・構造化データ座標（35.486148, 139.653484）を照合し、1件の確認済みカタログとして保持しています。東横INN／東横イン・全角半角・空白を正規化して検索します。他の施設はNominatim検索へフォールバックし、全ホテルの名称検索に対応済みという意味ではありません。

指定名称での検索・住所候補・ピン座標・再計算・保存復元をブラウザで検証済みです（経路は固定応答、検索候補は公式確認済みの実データ）。

### 宿泊地変更後の自動調整

宿泊地を検索で置き換えたり、ピンを移動すると、チェックが有効な場合はその地点までを残して後続候補を約25kmごとに配置し直します。元の全線ルートに変更地点を投影して残りの道路形状を分割する目安で、宿までの寄り道により実際の日別距離は変わります。5km以上ルートを離れた地点や全線を取得できない場合は自動調整をせず案内します。後続の手動設定も置き換わるため、チェックで無効化でき、自動調整前の後続地点へ戻すボタンもあります。

### 東海道付近の東横INN（公式位置データ）

2026-11-10時点の公式ホテル一覧から、東京都・神奈川県・静岡県・愛知県・三重県・滋賀県・京都府の125施設について公式ページの住所・構造化データ座標を取得し、現行全線徒歩ルートから直線5km以内の83施設を `src/toyoko-hotels.json` に収録しました。施設ごとに出典URLを保持しています。対象と除外の記録は `research/toyoko-coverage.json` にあります。

地図の青い「東」ピンから公式サイトを開く、宿泊候補にする、名前で検索する操作ができます。表示チェックでまとめて非表示にもできます。基準は旧東海道の確定線ではなくアプリの現在の徒歩線です。施設の営業継続・料金・空室・徒歩での寄り道距離は別途確認してください。新規開業等は自動反映されずデータ更新が必要です。

宿泊候補の確定画面では「何泊目に設定しますか？」から、既存の泊数の置き換え、または最後の泊として追加を選べます。周辺ホテル一覧から選んだ際は元の泊数を初期選択します。既存地点を置き換えた場合は、設定に応じて後続の約25km自動調整も実行します。

### 宿泊地の自動調整ロック

日別カードの「固定する」で自動調整ロックを切り替えます。ロックした地点は場所・泊数を維持し、固定地点の間は既存の泊数に合わせ均等配置します。このため1日25kmにならない場合があります。最後の固定地点以降は約25km間隔です。25kmプランの再作成にもロックを適用します。手動の変更・削除・並べ替えは可能で、ロックは自動調整のみを防ぎます。順序がルートと逆転したり固定地点がルートから離れすぎた場合は、自動調整を行わず既存計画を維持します。

「ロックしていない地点をならす」は既存の泊数を維持し、日本橋・固定地点・京都の間で未固定の候補を道路距離で均等配置します。最終の京都到着点が未登録でも、京都を終端の基準として配置し、到着点を勝手に追加しません。「自動調整前に戻す」で取り消せます。元ルート上の均等配置のため、宿への寄り道を含む再計算値には差が生じます。

### 追加3チェーン

2026-11-10に公式一覧・公式アクセス情報から確認したコンフォートホテル12施設、スーパーホテル38施設と、公式施設名・所在地とOpenStreetMapの位置を照合したホテルルートイン3施設を追加。`src/chain-hotels.json` に施設別の出典と位置の出典を記録しています。現行徒歩ルートから直線5km以内の採用条件です。チェーンごとの表示切り替え・施設名検索・宿泊候補への追加に対応。

公式一覧の入口: https://www.choice-hotels.jp/hotel/hotellist/ 、 https://www.superhotel.co.jp/hotel_js.php 、 https://www.route-inn.co.jp/hotel_list/ 。スーパーホテルで緯度経度の逆記載があるものは日本国内の範囲として補正。コンフォートは公式アクセスページの地図座標を使用し、入口そのものを保証しません。ルートイン公式地図リンクは取得不可で、3施設以外は未収録です。調査の未収録記録は `research/chain-hotel-coverage.json` に保存。ルートインの位置データは © OpenStreetMap contributors、ODbL（https://www.openstreetmap.org/copyright）。全施設の網羅・営業継続・低価格は保証していません。

### 旧東海道のKML/KMZ参考表示

マップ内に、手元のKML/KMZを読み込む機能を追加しました。紫の参考線はファイル内のLineStringを表示し、区間の切れ目を勝手につなぎません。ファイルは送信・公開せず、ページの再読み込みで消えます。青い現代徒歩ルート、日別の距離計算、25kmプランは従来どおりです。

ユーザー提供の3サイトの取得状況・利用条件は `research/provided-historic-route-sources.md` に記録しています。公開アプリへ配布できる全線データは未取得であり、史実上の旧東海道への全面置換は未完了です。

個人利用用の実データを端末内で読み込む場合、水路・徒歩不可と名前に明記されたLineStringは青緑の点線で表示します。端末内での利用と、公開リポジトリでの再配布は区別します。元データを本リポジトリへ同梱していません。
